Install

Three commands to a working platform.

On a fresh Debian or Ubuntu box, the installer brings in whatever's missing and leaves Mangrove running as a systemd service.

  1. Installs Docker, Caddy, Go and Node if they're not already there.
  2. Builds the dashboard and the single mangrove binary.
  3. Asks whether the box has a public IP or sits behind a home router, and sets up dynamic DNS if it needs to.
  4. Claims the instance with a one-time setup token and creates your owner account.
SHELL · YOUR SERVER
$ git clone https://github.com/evanxdsouza/mangrove.git
$ cd mangrove
$ sudo ./setup.sh
# Re-running it is safe: every step checks what's already there.

What you get

The real PaaS feature set, not just a container runner.

Everything you'd expect from a hosted platform, on one small machine you control.

Push to deploy, with staging and PR previews

Link a GitHub repo and every push redeploys it. Spin off staging environments that track their own branch, then promote the exact commit they're running into production with one click. Opt in to a preview for every pull request, with a bot comment that links to it and tears it down when the PR closes.

Blue/green, with rollback

A new version only takes traffic once it passes its health check. If it never does, the old one keeps serving. Roll back to any earlier deploy from its history.

Domains and HTTPS

Point a domain at a deployment from its dashboard, and Caddy gets and renews the certificate. Behind a home router with no static IP? The built-in DDNS updater handles it.

One-click templates

Common self-hosted apps without writing a Dockerfile.

Logs and a real shell

Live log streaming and one-off commands from the dashboard, and a full interactive shell from the terminal UI.

Workspaces and roles

Group projects by team, client or environment. Give people admin, editor or viewer access per workspace. Everything is in the audit log.

Self-healing

Optionally restart a service that keeps failing its health check, and retry a failed deploy with backoff.

Idle sleep

Let quiet apps stop after a while and wake on the next visit, so a small box can hold more of them.

Password-protected apps

Put a deployment behind a password or a Mangrove sign-in, and leave chosen paths open.

Turn a drive into a NAS

On a home server, mount a plugged-in drive and share it over SMB, through a small separate helper so the control plane never needs mount rights.

Backups in one command

mangrovectl backup captures the database and its encryption key together, from the box or from your laptop.

Simple mode

A plain-language "your apps" view for people who want a blog running, not a build strategy. Same platform underneath.

Read it at a glance

Status, told by the tide.

Every project and deployment carries a tide gauge. High water means it's running. A moving tide means it's building or checking health. Low water means it's resting. A dry gauge with a red rim means it needs you.

A project shows its worst deployment, so trouble never hides inside a group, and every gauge comes with a label that says the status in words.

Why self-host

The same workflow, on your terms.

A hosted PaaS runs on the vendor's hardware and bills by usage. Mangrove runs on hardware you already own or rent. The trade is that you're the ops team, and the dashboard does as much of that for you as it can.

A hosted PaaS

  • Priced per seat, per build minute, per GB
  • Your apps and data live on someone else's servers
  • Limits and pricing change when the vendor decides
  • Someone else is on call

Mangrove

  • No metering: the box costs what it costs
  • Everything stays on a machine you control, even one at home
  • Plain Docker containers and a SQLite file, nothing to be locked into
  • You're on call, with rollback, self-healing and backups to help
Under the hood

Small on purpose.

Built and tested day to day on a 2 vCPU, 2 GB, 16 GB-disk VPS, alongside the apps it runs.

Go

One binary with the dashboard embedded. No Node server at runtime.

SQLite

The single source of truth, in one file. Secrets in it are encrypted at rest.

Docker

Builds and runs everything: Dockerfiles, Nixpacks, compose files, images, static sites.

Caddy

Reverse proxy and automatic TLS, driven entirely through its admin API.
